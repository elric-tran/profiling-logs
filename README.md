# ProfilingLogs

ProfilingLogs is an ASP.NET Core and EF Core request profiler with a built-in web UI for replaying requests, comparing API versions, and digging into SQL execution details.

It captures the HTTP request, the generated SQL, execution timings, connection events, and the source line that triggered each query. The results page is designed for day-to-day debugging rather than raw log spelunking.

## Highlights

- Request timeline with method, endpoint, status, duration, and query count.
- Request detail view with captured SQL, per-query timings, caller line links, and execution plan access.
- Reply action to replay the original request with the captured Authorization header and body.
- cURL export for copying a request into Postman or a terminal.
- Compare API Versions modal for side-by-side request comparison.
- SQL diff popup with side-by-side and unified `+/-` views.
- Index Analyst tab that inspects execution-plan index usage and lets you generate DROP/CREATE scripts.
- Toast notifications instead of browser alerts.
- Durable file-backed storage so captured requests survive app restarts.
- Full exception capture, including stack traces and handled 500 responses.
- Clear flow that preserves selected requests used for compare or detail.

## What it captures

For each profiled request:

- HTTP method, URL, headers, request body, status code, and duration
- version tag generated at application startup
- SQL statements generated by EF Core
- per-query duration and error messages
- connection open/close events
- source file, line number, and method that produced the SQL

If a request fails, ProfilingLogs stores the full exception text and any response body returned by the app so the UI can show the failure in context.

## Web UI

Open the results page at:

`{RouteBasePath}/results-index`

Default:

`/profiler/results-index`

The UI includes:

- request table with per-column search for method, name, and endpoint
- always-visible table header and filters, even when there are no results
- reply and cURL actions per request
- compare selection with checkbox rows
- side-by-side request comparison
- SQL diff popup with whitespace-insensitive comparison and a unified diff mode
- execution-plan viewer with a dedicated Index Analyst tab
- script popup for index DROP/CREATE generation

## Install

```bash
dotnet add package ProfilingLogs
```

## Quick start

```csharp
using ProfilingLogs;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddProfilingLogs(o =>
{
    o.Enabled = builder.Environment.IsDevelopment();
    o.Ide = ProfilingIde.Cursor;
});

var app = builder.Build();

app.UseProfilingLogs();

app.Run();
```

You can also bind configuration from `appsettings.json`:

```csharp
builder.Services.AddProfilingLogs(builder.Configuration.GetSection("ProfilingLogs"));
```

```json
{
  "ProfilingLogs": {
    "Enabled": true,
    "RouteBasePath": "/profiler",
    "Ide": "Cursor"
  }
}
```

## Options

| Option | Default | Description |
|---|---|---|
| `Enabled` | `false` | Master switch. When `false`, everything is a no-op. |
| `RouteBasePath` | `/profiler` | Base path for the embedded UI and API endpoints. |
| `EnableVsCodeLinks` | `true` | Linkify IDE deep-links in the results page. |
| `EnableConnectionColors` | `true` | Show colored connection open/close markers. |
| `EnableCallerComment` | `true` | Inject source-line comments into SQL. |
| `HideDefaultConnRows` | `true` | Hide default EF connection rows. |
| `EnableClearCacheButton` | `true` | Show the Clear All button in the UI. |
| `SqlNamespaceFilter` | `"Services"` | Restrict caller stack scanning to matching namespaces. |
| `Ide` | `VSCode` | `VSCode`, `Cursor`, `Rider`, `VisualStudio`, or `Custom`. |
| `IdeUrlFormat` | `null` | Custom deep-link format. Supports `{path}`, `{line}`, `{col}`. |
| `PathMap` | `null` | Optional remote-to-local path mapping. |
| `ColorScheme` | `Dark` | UI theme. |

## Notes

- `EnableCallerComment` changes the SQL text sent to the database. Keep it enabled only when you want source-line traceability.
- IDE deep-links work best when the browser and source code are on the same machine, or when `PathMap` is configured.
- `VisualStudio` deep-links use a protocol handler; `VSCode`, `Cursor`, and `Rider` work directly.
- Captured requests are persisted to `profilinglogs-store.json` beside the app output so they survive restarts.
- GitHub Packages restore may require authentication with a PAT.
